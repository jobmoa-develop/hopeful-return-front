# hopeful-return 프로젝트 구조 (공유용)

> 작성 시점: 2026-06-26 · 단계: **기본 구조(인프라 스켈레톤)** — 도메인/DB 스키마/화면은 미확정.
> 토대로 사용할 수 있는 골격만 맞춘 상태.

---

## 1. 전체 개요

| 구분 | 레포 | 스택 | 로컬 폴더 |
|------|------|------|-----------|
| 백엔드 | `jobmoa-develop/hopeful-return-backend` | Spring Boot 3.5.5 / Java 17 / Gradle | `hopeful_return_backend` |
| 프론트 | `jobmoa-develop/hopeful-return-front` | React 19 / Vite / TypeScript | `hopeful_return_front` |

- 두 레포는 **분리**되어 있습니다. 각 레포내에 `/docs` 폴더가 따로 존재합니다.
- DB: **MSSQL**, 캐시/임시저장: **Redis**
- 배포(예정): Ubuntu 24.04, 백엔드 포트 **3434**

### 기본 브랜치 / 협업
- 브랜치: `main`(운영) / `develop`(통합·**기본 브랜치**) / `feature/<be|fe>-<설명>` / `fix/*`
- 작업 전 **이슈 등록 + 본인 assignee 지정** → 작업 겹침 방지 (자세한 규칙은 각 레포 `docs/BRANCHING.md`)
- 라벨: `type:*`, `area:*`, `prio:*`, `status:*`, `owner:me|teammate`
- 이슈/PR 템플릿, CODEOWNERS, CI(GitHub Actions) 구성됨
- 레포는 **public** 입니다. `main`/`develop` 에 **branch protection 적용**(PR + 1인 리뷰 승인 필수, force-push/삭제 금지; 레포 admin 은 우회 가능)
- ℹ️ GitHub Projects(v2) 보드는 미생성(토큰 `project` 스코프 없음) — 라벨/마일스톤/assignee 로 운영

## 2. 백엔드 (`hopeful_return_backend`)

### 2.1 스택 / 주요 의존성
- Java 17, Spring Boot 3.5.5 (Gradle, `build.gradle`)
- Web, Validation, **Security**, **Data JPA**, **Data Redis**, **Mail(SMTP)**, Actuator
- **Flyway** (`flyway-core` + `flyway-sqlserver`), **MSSQL JDBC**
- **JWT**: `io.jsonwebtoken:jjwt 0.12.6`
- Lombok, 테스트(`spring-boot-starter-test`, `spring-security-test`)

### 2.2 디렉토리 구조
```
hopeful_return_backend/
├── build.gradle / settings.gradle / gradlew*       # Gradle (rootProject: hopeful-return-backend)
├── docker-compose.yml                              # 로컬 인프라(MSSQL+Redis+DB초기화)
├── .env(.example)                                  # 로컬 환경값 (.env 는 gitignore)
├── docker/
│   ├── spring/Dockerfile                           # 멀티스테이지(빌드→JRE) 배포 이미지
│   └── nginx/nginx.conf                            # 리버스 프록시 예시
├── docs/ (BRANCHING.md, DOCKER.md)
├── .github/ (ISSUE_TEMPLATE/, pull_request_template, CODEOWNERS, workflows/ci.yml)
└── src/main/
    ├── java/com/jobmoa/hopefulreturn/
    │   ├── HopefulReturnApplication.java            # 진입점
    │   ├── config/      SecurityConfig              # stateless, CORS, JWT 필터 등록
    │   ├── security/    JwtTokenProvider            # 토큰 생성/검증/role 추출 유틸
    │   │               JwtAuthenticationFilter      # 클레임 기반 인증(DB 비의존)
    │   ├── common/      ApiResponse                 # 공통 응답 envelope {success,data,error}
    │   │               ErrorCode / BusinessException
    │   │               GlobalExceptionHandler       # 전역 예외 → ApiResponse.error
    │   ├── email/       EmailService(SMTP)          # 메일 발송
    │   │               EmailVerificationService     # 인증코드 발급/검증(Redis TTL)
    │   ├── sms/         SmsService(interface)        # 추후 실제 provider 구현
    │   │               NoOpSmsService               # 로그만 남기는 기본 구현
    │   └── web/         PingController               # GET /api/ping (연결 확인용)
    └── resources/
        ├── application.yml                          # 공통(JPA validate, Flyway, JWT, Mail, 포트)
        ├── application-local.yml                    # 로컬(localhost:14330 MSSQL, 16379 Redis)
        ├── application-dev.yml                      # 컨테이너 네트워크(mssql/redis 호스트명)
        ├── application-prod.yml                     # 운영(env 주입)
        └── db/migration/.gitkeep                    # Flyway 폴더(현재 마이그레이션 없음)
```

### 2.3 현재 "있는 것 / 없는 것"
- **있음(재사용 인프라):** 공통 응답/예외, Security + JWT(유틸·필터), 이메일(SMTP)+Redis 인증코드, SMS 인터페이스, `/api/ping`
- **없음(의도적 미구현 — 확정 후 추가):** 회원/도메인 엔티티, 로그인/회원가입 API, **DB 스키마(Flyway 마이그레이션)**
- JPA `ddl-auto: validate` + 엔티티 0개 → 검증 대상 없음. Flyway 는 "No migrations" 로 정상 부팅.

### 2.4 API (현재)
| Method | Path | 인증 | 설명 |
|--------|------|------|------|
| GET | `/api/ping` | 공개 | `{"success":true,"data":"pong"}` (연결 확인) |
| GET | `/actuator/health` | 공개 | 상태(UP/DOWN) |
| 그 외 `/**` | — | **인증 필요** | JWT 토큰의 클레임(subject+role)으로 인증 |

### 2.5 설정 / 프로파일
- 프로파일: `local`(호스트 실행) / `dev`(docker compose 내부) / `prod`(운영)
- 환경변수: `DB_PASSWORD`(필수, env 주입), `JWT_SECRET`, `MAIL_*`, `DB_NAME`, 포트 등 — `.env` 참고
- 메일 헬스체크는 SMTP 미설정이라 비활성(`management.health.mail.enabled=false`)

    ├── routes/AppRoutes.tsx        # 라우팅 ( / → HomePage )
    ├── pages/HomePage.tsx          # 환영 + 백엔드 /api/ping 연결 확인 버튼
    ├── api/client.ts               # axios 인스턴스 + 토큰 인터셉터(요청), 401 처리(응답)

### 3.3 현재 "있는 것 / 없는 것"

## 4. 로컬 개발 환경 (Docker)

### 4.1 포트 (호스트)
| 서비스 | 호스트 포트 | 컨테이너 | 비고 |
|--------|------------|----------|------|
| MSSQL | **14330** | 1433 | 호스트 네이티브 SQL Server(1433)·PostgreSQL 충돌 회피 현재 로컬내 다른 프로젝트를 위해 사용중 |
| Redis | **16379** | 6379 | |
| Backend | 3434 | 3434 | |

### 4.2 실행 순서
```bash
# (백엔드 레포에서)
cp .env.example .env        # DB_PASSWORD 등 값 확인 (특수문자 #,! 회피 — '_' 권장)

# 방법 1) 전체 컨테이너 (가장 간단)
docker compose --profile app up --build

# 방법 2) 인프라만 컨테이너 + 백엔드는 로컬
docker compose up -d
export DB_PASSWORD=$(grep '^DB_PASSWORD=' .env | cut -d= -f2)
./gradlew bootRun --args='--spring.profiles.active=local'

# 동작 확인
curl http://localhost:3434/actuator/health   # {"status":"UP"}
curl http://localhost:3434/api/ping          # {"success":true,"data":"pong"}

# (프론트 레포에서)
npm install
npm run dev                 # http://localhost:5173 → Home 에서 백엔드 연결 확인
```
> 검증 완료(2026-06-26): 위 절차로 health UP / ping pong 확인. 자세한 내용은 백엔드 `docs/DOCKER.md`.
